# EF Core SQLite Dashboard Design

## Goal

Create a simple console project that demonstrates normal Entity Framework Core usage with SQLite. The application will store categories and products, show common LINQ queries, print the SQL generated by EF Core, and then print the executed results.

## Project

Add `EfCore_Sqlite_Dashboard` as a console project targeting the repository's current .NET version and add it to `CompositeFileSystem.slnx`.

## Domain model

- `Category`: integer key, name, and a collection of products.
- `Product`: integer key, name, price, stock quantity, and foreign key to category.
- `CatalogDbContext`: SQLite-backed EF Core context with a required one-to-many category/product relationship.

The database will be a local `catalog.db` file in the project working directory. Startup will recreate and seed it with deterministic sample data so every demonstration run produces the same output.

## Dashboard flow

The console application will run these operations in order:

1. List products with their category names.
2. Search products by a sample name fragment.
3. Group products by category and show counts.
4. Calculate total inventory value by category.

Each operation will print its human-readable purpose, the LINQ query description, `ToQueryString()` output, and the materialized results. Queries will remain as `IQueryable` until SQL is displayed and the result is enumerated.

## Teaching boundaries

This example intentionally uses EF Core normally and contains no visitor abstraction. It demonstrates the boundary between the object model, LINQ expression, generated SQL, and materialized result. It will not add migrations, a repository layer, or a service layer; database initialization is sufficient for this self-contained teaching sample.

## Verification

Build and run the new project. Confirm that SQLite creates the database, seed data is available, every dashboard operation prints SQL before results, and the results are deterministic.
